# Security policy

## Supported versions

Only the latest release of each project receives security fixes. Please check that the
problem still happens with it before reporting.

## Reporting a vulnerability

Please don't open a public issue for a security problem.

Report it privately through GitHub instead: open the **Security** tab of the repository
concerned and click **Report a vulnerability**
([how private reporting works](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)).
Only you and the maintainer can see the report.

Please include what you can of the following:

- the version or commit you tested and your operating system,
- the steps to reproduce, or a proof of concept,
- what an attacker could achieve with it.

## What happens next

- I aim to acknowledge the report within 7 days.
- Once the vulnerability is confirmed, I'll work on a fix and release it, ideally within
  90 days of the report.
- The fix comes with a published security advisory, crediting you unless you'd rather
  stay anonymous. Please keep the details private until then.
